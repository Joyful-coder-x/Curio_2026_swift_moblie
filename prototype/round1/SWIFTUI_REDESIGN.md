# Assignment · Apply the Curio design to the existing SwiftUI prototype

Open [the existing Xcode project](cuiro%20round1/cuiro%20round1.xcodeproj). Start from the current main branch. Deliver changes in its existing SwiftUI target and simulator demo flow. This is a UI revision; Firebase integration is a separate assignment.

Use the [palette and dimensions](../../docs/design/Curio_Visual_Guide.md) for measurements, [Discover](ui/Discover.jpg) for the latest Home, [Inbox](ui/Inbox.jpg) for the conversation, and [the combined preview](ui/Unified_UI.jpg) for Mine and shared components. The latest Discover image supersedes the brand header in older previews. The [page inventory](UI_INVENTORY.md) records open design questions.

1. **Set the theme once.** Create named sRGB colors using the 12 hex values in the guide. Apply Canvas to screens, Paper to prints and navigation, Ink to captions, Plum to the profile header, Action to primary controls, Selected to the active tab, and Received/Sent to the corresponding bubbles. Use a scalable 15 pt italic serif for print captions and scaled system sans text for metadata. Use the native safe area and at least 44 pt touch targets.
2. **Build one reusable cover.** Pass the ordered photos, current viewer, archive status and presentation size to the same SwiftUI cover used by Discover, Inbox and Mine. One thread gets one paper frame: square image at the top, original prompt inside the broad bottom margin, metadata outside. At 1 photo use a single image, at 2–4 use 2×2, at 5–9 use 3×3. Fill active empty cells with stable photo-derived colors; cache the palette per accepted photo and use its fixture color for symbol-only samples. At archive use a fixed 3×3, blank unused cells, and the viewer’s contribution in the center (opener for visitors).
3. **Home and Mine — ContentView.swift / CurioStore.swift.** Replace the full-width ThreadCard list and top section picker with a two-column LazyVGrid and bottom Home / Inbox / Mine navigation, retaining a reachable New invitation action and demo controls. Remove the Curio brand header and star. At 390 pt viewport, use 22 pt page insets, 14 pt column gap, 18 pt row gap, 166 pt card, 150 pt square image, 7 pt paper padding, 1 pt outline and a caption area at least 38 pt high. Use flexible columns on other widths. Below each Discover print show author initial and name, real count out of nine and remaining time. Seed 24 public community samples alongside the open starter invitation so scrolling works without using up the A–J test users’ publication allowances. Show only eligible open threads. Mine gets the profile header, All / Created / Joined filters, Active by nearest deadline and Saved journals by most recent archive.

   Current additions: Discover switches between Random and Following creator feeds. Mine includes a Following row/list. The account switcher lives under a top-right settings gear and labels stable A–J simulator scenarios. Active paper frames interpolate from `#FFFCF5` toward `#502653` as the 600-second deadline approaches; saved prints remain `#502653` with light captions. The local role fixtures keep B/Jun saved-only, A/Maya creator-only and C/Rea join-only with retained earlier chat. These fixture roles do not replace Firebase authorization.
4. **Inbox and thread — ContentView.swift / ThreadViews.swift.** Group events by thread ID. Show one row per group, latest accessible activity first, with a 55 pt collage thumbnail, prompt, preview and time. For round one, a delivered invitation may show a generic invitation preview; only accepted contributors can see chat. In ThreadView merge accepted photos and messages chronologically. Each accepted photo automatically renders one author entry with the image below it. Left-align others’ messages and right-align the viewer’s. Use the 118 pt photo and 78% maximum bubble width in the guide. Open the existing thread or journal route on tap.
5. **Apply the theme to compose and journal.** In PhotoFormView keep camera/library → square crop → review/retake → explicit final submission. Keep the submitIsArmed protection: confirming the crop must never publish or join automatically. Creation takes a prompt and audience; joining uses the existing prompt. Retain visitor, member, full and expired behavior. In JournalView reuse the archive cover layout; show contributors, sharing and member-only read-only history. Defer new layouts for onboarding, settings, blocking and invitation management.
6. **Verify and hand back.** Build the current Xcode target. In the simulator, record A publishing and B joining, exchanging messages and reopening the journal. Check 1, 3, 4, 5 and 9 photos, an underfilled archive, creator and contributor center positions, and a visitor without chat access. Confirm 9/9 leaves Discover while members can chat until the 10-minute test deadline. Toggle all Mine filters, scroll to the last Discover item, and test a long prompt and enlarged text on a narrower device. Double-tap crop confirmation and verify zero submissions until the separate final button is used. Deliver the commit, simulator/device and OS used, comparison screenshots of Discover, Inbox, timeline and Mine, and a short pass/fail list.
